Contributing Scientific Skills

Thank you for contributing to the Science Skills collection.

Science Skills are intended to make scientific agent workflows more accurate, reproducible, grounded, and token-efficient.

Contribution Principles

A useful contribution should:

* solve a recognizable scientific workflow problem;
* minimize unnecessary context retrieval;
* prefer authoritative scientific sources;
* preserve provenance;
* distinguish evidence from hypothesis;
* provide reproducible computational procedures;
* identify uncertainty and limitations;
* avoid presenting speculative results as established science.

New Scientific Frameworks

Contributors proposing a new scientific framework or computational methodology should provide:

1. a clear definition of the framework;
2. its variables and assumptions;
3. comparison with established methods;
4. reproducible examples;
5. appropriate references;
6. falsifiable predictions where applicable.

New terminology should be clearly identified as framework-specific terminology.

Data Sources

When a skill uses external scientific resources, contributors should document:

* database/tool name;
* source URL or identifier;
* version or release where available;
* applicable license;
* intended use;
* relevant limitations.

Examples may include AlphaGenome, AlphaFold DB, UniProt, structural biology resources, genomic databases, chemical databases, literature indexes, and other scientific tools.

Validation

Contributors should test skills against representative scientific questions.

Where numerical calculations are involved, include:

* known baseline results;
* test inputs;
* expected outputs;
* unit checks;
* reproducibility instructions.

Scientific Claims

Contributions should use conservative language.

Prefer:

“The model predicts…”

over:

“The model proves…”

unless the statement is supported by appropriate independent evidence.

A computational result should not be presented as experimental validation unless experimental validation actually exists.

Pull Requests

Pull requests should briefly describe:

* the scientific workflow addressed;
* the files added or changed;
* the sources used;
* the validation performed;
* known limitations.

The goal is to make scientific AI agents more capable while maintaining scientific transparency and reproducibility.
